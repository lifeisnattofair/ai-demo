# 수치 기록 (맥락 있는 수치만)

## 1단계. 요구사항 정의
- 브레인스토밍 질문: 7개 + 구현 방식 선택 1개 → 기획 점검표 8항목
- 검토자(builder check) 질문: 6개 → 사용자 결정 3건(대기 수량, 시연 환경, 환경 분리), AI 판단 3건(반올림, 경과 비율 경계, 할인 매수) → 점검표 7항목 추가(총 15항목)
- 요구사항 64개: SFR 26, PER 4, SER 8, DAR 6, SIR 6, QUR 7, COR 7
- 범위 밖 항목: 8개 구분 / 완료 조건(AC): 9개
- 성능 요구사항 4개 중 프로토타입 실측 1개(PER-004 중복 확정 0건), 나머지는 목표치만

## 1.5단계. 디자인 콘셉트
- 조사한 레퍼런스: 사용자 7개(Refero 5 + 수상작 2), 관리자 4개(1차 3개는 「사용자 페이지 같다」 피드백으로 교체)

## 2단계. 구현 계획
- Task 18개(Task 0~16 + 8A): 정책 2, DB 3, 결제 2, 디자인 시안 1, 사용자 화면 5, 관리자 화면 3, 골격/배포 2
- 요구사항 추적표 64행: 자동 테스트로 검증 46개, 수동(QA)만 9개, 목표치나 문서, 리뷰 확인 9개(PER-001~003, SER-008, DAR-005, COR-004~007)
- 사전에 정한 「테스트가 안 짚는 위험」(Review Focus) 5개 → 각각 테스트로 고정
