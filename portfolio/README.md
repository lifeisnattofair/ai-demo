## 1단계. 요구사항 정의 (완료, 2026-11-23 승인)

- **스킬**: superpowers:brainstorming
- **산출물**: `docs/superpowers/specs/2026-11-23-booking-platform-requirements.md`, `docs/superpowers/specs/2026-11-23-booking-platform-design.md`, `docs/superpowers/notes/planning-checklist.md`
- **내가 내린 결정과 이유**
  - 추진 배경: 공연은 외부 예매처, 교육은 전화/구글폼으로 창구가 나뉘어 정원, 예약자, 결제 내역이 흩어짐 → 신규 통합 구축.
  - 범위: 단계적 대체(C안). 1차는 교육 + 자체 기획공연, 대관공연은 외부 예매처 유지(2차 과제). 공공사업의 1차/향후 과제 구분을 그대로 보여 주기 위해.
  - 회원 전용 예약: 1인 한도, 할인, 중복 방지를 계정 기준으로 관리하기 위해.
  - 교육은 체험(단회차)과 정규 강좌(다회차) 둘 다 → 정규 강좌는 「과정」 단위 판매, 개강 후 환불은 평생교육 반환 기준(1/3 전 2/3, 1/2 전 1/2, 이후 불가).
  - 대기 승격 결제 기한 24시간, 개강 후 추가 모집 없음.
  - 범위 밖 목록과 완료 조건 9개는 AI 제안을 그대로 채택.
- **AI가 짚어 준 빈칸/예외**
  - 외부 예매처를 남기면 좌석 이중 판매 연계가 핵심 난제가 된다 → 범위 결정의 근거.
  - 비회원 예약을 허용하면 1인 한도가 무력화된다.
  - 다회차 강좌는 개강 후 중도 취소 환불 기준이 따로 필요하다.
  - 장애 여부는 개인정보보호법상 민감정보 → 증빙 파일 업로드 대신 현장 확인으로 보안 범위를 줄임.
  - 대기 승격 자동 결제는 빌링키가 필요해 범위가 커진다 → 승격 알림 후 기한 내 결제 방식.
  - D-2 이내 취소분은 승격 대신 일반 판매로 전환.
  - 성능 목표는 RFP 형식대로 적되 프로토타입에서는 동시성 정합성만 실측한다고 명시.
  - 검토자 점검: 대기 승격 때 취소분이 신청 수량보다 적은 경우, 기한과 D-2가 겹치는 경계, 정확히 1/3 지점, 1원 반올림 위치, 검수용 시계가 공개 시연에 새는 문제.
- **기술 판단**: AI 기본 조합(Next.js, React, Tailwind) 대신 Vite + 바닐라 JS + KRDS를 선택했다. 정적 배포에 맞고, 공공 UI 기준 디자인 시스템을 따르기 위해서다. DB는 MariaDB를 검토했지만 무료 호스팅 제약 때문에 PostgreSQL(Supabase)을 쓰고, 실사업 전환표(전자정부 표준프레임워크 + MariaDB/Tibero)를 남겼다.
- **바꾼 결정**: 호스팅을 Netlify Functions에서 GitHub Pages + Supabase로 바꿨다(Netlify 무료 한도 부족). 공개 시연과 검수 환경을 Supabase 프로젝트 2개로 나눴다.
- **힘들었던 점**: 정책 하나하나는 단순한데, 둘이 겹치는 경계(대기 기한 × D-2, 할인 × 동반 매수)에서 빈칸이 생겼다. 대화로 정한 것만으로는 부족했고, 맥락 없는 검토자에게 문서를 다시 읽히는 단계가 필요했다.
- **걸린 시간**: 약 1시간(질문 8회 + 문서 작성 + 검토 1회)

## 1.5단계. 디자인 콘셉트 (완료, 2026-11-23)

- **스킬**: superpowers:brainstorming(이어서), 레퍼런스 조사는 내장 브라우저로 Refero Styles 검색
- **산출물**: 설계 문서 5-9절 「디자인 콘셉트」
- **내가 내린 결정과 이유**
  - 사용자 화면은 공연 포스터로 다채롭게 하되 예약 UX는 깔끔/직관적으로 → 「포스터가 색을 맡고 UI는 무채색, 행동 버튼은 KRDS 대표 색 하나」
  - 관리자 화면은 업무 편의성 1순위, 일반적인 공공 관리자 느낌(좌측 메뉴 나열) → 공공 관리자 표준 틀(조회 조건 → 목록 → 상세)
- **바꾼 결정**: AI가 처음 고른 관리자 레퍼런스(Modern Treasury, Airtable, Equals)는 모두 마케팅 사이트 톤이라 「사용자 페이지 같다」는 피드백을 받았다. 전자정부 표준프레임워크 공통컴포넌트, Ant Design Pro, CoreUI 같은 업무형 레퍼런스로 다시 찾았다. Modern Treasury는 정산 표의 톤만 남겼다.
- **AI가 짚어 준 것**: 실제 공연 포스터는 저작권 문제가 있어 SVG 가상 포스터를 직접 제작한다. 상태 색 칩에는 글자를 함께 써서 색에만 의존하지 않게 한다(접근성).
- **걸린 시간**: 약 20분

## 1단계 산출물 문서화 (2026-11-23)

- **사용자 지시**: 산출물은 md가 아니라 실제 산출물처럼 hwp, word, xlsx, pdf로 만든다. HTML로 만든 뒤 PDF로 일괄 저장해도 된다.
- **산출물**(`deliverables/`)
  - `01_요구사항정의서_v1.1.pdf`(26쪽): 표지, 개정 이력, 목차(쪽 번호 자동), Ⅰ~Ⅵ장, 요구사항 64개를 공공 양식 상세표로 정리(고유번호, 분류, 명칭, 세부 내용, 검수 기준, 산출 정보)
  - `01_기획점검표_v1.0.pdf`(3쪽, 가로)
  - `02_요구사항추적표_v1.0.xlsx`: 추적표(64행, 틀 고정, 자동 필터, 인쇄 설정), 분류별 요약(COUNTIF 수식), 검수 기준, 개정 이력 시트
- **만드는 방법**: md 원본 → `tools/deliverables/build.mjs`가 공공 문서 양식 HTML로 변환 → Paged.js로 쪽 나눔, 머리말, 쪽 번호 → 크롬으로 PDF 저장. XLSX는 exceljs로 생성. 원본을 고치면 `npm run build` 한 번으로 산출물 전체를 다시 만든다.
- **캡처**: `portfolio/shots/deliverables/`(표지, 개정 이력, 목차, 목표 시스템 개요, 상세 요구사항, 기획 점검표). XLSX 캡처는 엑셀에서 직접 찍는 편이 자연스러워 남겨 둠.
- **검수하며 고친 것**: 표지가 다음 쪽으로 밀려 1쪽이 비는 문제, 점검표 표의 열 너비가 다른 표에도 적용돼 글자가 세로로 쌓이던 문제, 「D-7~D-4」의 물결표가 취소선으로 바뀌던 문제

## 2.5단계. 디자인 시안 (Task 8A, 2026-11-23 사용자 확정)

- **산출물**: `design/mockups/` 반응형 HTML 시안 7장(사용자 5: 목록, 상세, 좌석, 할인/결제, 내 예약 / 관리자 2: 예약 내역, 정산 현황), 디자인 토큰 `assets/css/tokens.css`(KRDS 1.1.0 토큰 재선언), 사진 출처 `assets/photos/CREDITS.md`
- **캡처**: `portfolio/shots/mockups/` 14장(각 화면 PC 1440, 모바일 390 전체 페이지)
- **사용자 지시 반영**: 바로 출시 가능한 완성도, 설명용 문구/UI 없음, 강조 막대 금지, 사진 포스터, 가운뎃점/긴 줄표 금지
- **디자인 판단**
  - 사용자 화면: 화면은 무채색, 색은 포스터 사진과 행동 버튼(KRDS primary #256ef4)에만. 포스터는 사진 위에 시리즈명, 제목, 부제, 기간/장소를 같은 격자로 얹고, 밝은 사진(수채화)은 글자를 위쪽 어두운 색으로 바꿈
  - 예매 단계: 단계 표시 + 우측 고정 요약(남은 선점 시간, 선택 좌석, 금액). 결제 단계에 취소 수수료 일정을 날짜로 미리 보여 줌
  - 관리자 화면: 상단 바(자동 로그아웃 시간, 역할), 좌측 메뉴 트리, 조회 조건 상자(라벨 열 + 입력 열), 목록 표, 페이지 이동. 상태는 글자가 있는 색 칩, 개인정보는 가림 처리
  - 정산 수치는 「순매출 = 결제 - 환불」이 표, 카드, 그래프에서 모두 맞도록 계산
- **자체 점검에서 고친 것**: 밝은 포스터의 날짜가 사진에 묻힘, 좌석 판매 표시의 빗금이 시선을 흩뜨림, `.info` 클래스가 겹쳐 안내 상자 위에 검은 선이 생김, 예매/마이페이지 화면의 좌우 여백 사라짐, 390px에서 좌석도가 16px 넘침, 관리자 좌측 메뉴 배경이 첫 화면 높이에서 끊김

### 시안 전체 검토 (사용자 요청: 버그뿐 아니라 사용성, 애매한 UI, 태블릿과 중간 너비)
- **방법**: 1440, 1180, 1100, 1024, 960, 900, 860, 820, 768, 700, 600, 480, 430, 360px에서 가로 넘침을 자동으로 검사했다. 페이지 전체뿐 아니라 부모 상자 밖으로 삐져나온 요소까지 찾는 스크립트(`tools/deliverables/overflow.mjs`)를 썼다. 1024와 768은 캡처로 직접 보았다.
- **고친 것**
  - 정산: 일별 그래프 카드 아래가 비던 문제 → 그래프가 카드 높이를 채우고, 아래에 일평균/최고/최저를 넣어 옆 카드와 높이를 맞춤. 1024에서 정산표 마지막 열(순매출)이 가려지던 문제, 조회 조건이 라벨과 입력이 떨어져 줄바꿈되던 문제
  - 좌석: 900px에서 좌석도가 패널 밖으로 51px 넘침, 390px에서 좌석이 11px로 작아져 누르기 어려움 → 좌석은 20px 이상 유지하고 좌석도 안에서만 좌우로 밀게 바꿈, 처음에는 무대 중앙이 보이도록 함
  - 예매/결제 모바일: 남은 선점 시간과 다음 버튼이 긴 화면 맨 아래에 있던 문제 → 선점 시간은 상단에 고정, 금액과 다음/결제 버튼은 하단에 고정
  - 목록 1024: 대표 공연 포스터가 화면 폭만큼 커지던 문제 → 860px까지는 두 단 유지
  - 상세 768: 포스터가 왼쪽에 작게 남고 오른쪽이 비던 문제 → 포스터 240px + 정보 두 단
  - 마이페이지 모바일: 메뉴 이름과 건수가 붙어 보이던 문제 → 밑줄 탭 형태로 정리
  - 관리자 360px: 목록 도구 버튼이 상자 밖으로 넘침
- **결과**: 14개 너비 x 7장 모두 가로 넘침 0건. 캡처는 PC, 태블릿(768), 모바일 3종 21장으로 갱신
