# 한빛아트센터 통합 예약 플랫폼 QA 테스트 케이스

**문서 버전**: v1.0 (2026-11-24) / **대상**: 문화예술회관 통합 예약 플랫폼 프로토타입(main 브랜치, Vite + 바닐라 JavaScript + Supabase) / **근거 문서**: 요구사항정의서 v1.1(요구사항 64개, 검수 기준 AC-1~AC-9), 구현 계획의 요구사항 추적표

이 문서는 요구사항 64개와 검수 기준 AC-1~AC-9를 실행 가능한 검수 케이스로 풀어 쓴 것입니다. 사용자 화면(`index.html`, 해시 경로 `#/...`)과 관리자 화면(`admin.html`)을 브라우저로 확인하는 케이스, 자동 테스트(`npm test`, `npm run test:db`), 점검 스크립트(`npm run check:secrets`, `npm run check:trace`), 문서 확인으로 나뉩니다. 사용자 흐름 순서(가입/로그인, 목록/상세, 좌석/인원, 선점, 할인/결제, 예약 확인/취소, 대기, 알림, 관리자, 공통/보안/접근성/데이터)로 QA ID를 매기고, 마지막에 검수 기준 AC-1~AC-9를 종단 케이스로 둡니다. 모든 기관, 프로그램, 계정은 가상입니다.

**검수 환경**
- 로컬 실행은 README의 절차를 따릅니다: `npm ci`, `npx supabase start`(마이그레이션과 `supabase/seed.sql` 적용), `.env` 작성, `npm run dev`(사용자 화면 `http://localhost:5173`, 관리자 `/admin.html`). 결제가 필요한 케이스는 다른 터미널에서 `npm run functions:serve`를 실행해 둡니다.
- 환경 값(`app_settings.env`와 `VITE_ENV`): 검수용 시계가 필요한 케이스는 `local` 또는 `qa`, 시연 데이터 초기화와 시연 계정 보호는 `demo`(local에서도 초기화는 가능)에서 실행합니다. 공개 시연(demo)에서는 검수용 시계가 꺼집니다.
- 시연 계정(비밀번호 모두 `Demo-1234!`): member1@demo.test, member2@demo.test, member3@demo.test(회원), operator@demo.test(운영 담당), finance@demo.test(정산 담당). 케이스 안의 qa01, qa02, qa03 계정은 `@example.test` 이메일로 직접 가입해 만드는 가상 계정입니다.
- 각 묶음을 시작하기 전에 운영 담당의 시연 데이터 초기화(또는 `npx supabase db reset`)와 검수용 시계 초기화로 처음 상태를 맞춥니다. 모든 케이스는 시드 적용일과 같은 날 실행하는 것을 가정합니다. 다른 날 실행하면 하루 지날 때마다 시계 일수를 하루씩 줄입니다.
- 접근성 자동 점검은 개발 의존성 axe-core(4.10.3)를 개발 서버에서 화면에 불러 WCAG 2.1 A/AA 규칙으로 실행합니다(`/node_modules/axe-core/axe.min.js`). 카드 거절처럼 화면에서 만들 수 없는 상황은 자동 테스트로 확인하고 케이스에 그렇게 적었습니다.

**범례**
- 시드 데이터: 공연 「현의 대화」는 겨울 실내악 시리즈 「현의 대화」(회차1 D+10, 회차2 D+20), 연극제는 한빛 청소년 연극제 「우리들의 무대」(같은 일정), 소극장 좌석은 A~J열 x 20석(A~D열 R 40,000원, E~G열 S 30,000원, H~J열 A 20,000원). 체험은 가족 도자기 공방과 무대 분장 체험(회차 D+5, D+12, 정원 20, 10,000원). 정규 강좌는 시민 합창 교실 (12주)와 생활 수채화 (12주)(첫 수업 D+9, 주 1회 12회, 정원 15, 120,000원). D+n은 시드 적용일(한국 시간 0시)에서 n일 뒤입니다.
- 시계 표기: T+n일은 검수용 시계를 초기화한 뒤 +1일을 n번 누른 상태입니다. 회차 시작일이 D+10이면 T+3일이 D-7, T+7일이 D-3, T+10일이 당일입니다.
- 구분: 사용자(회원 화면), 관리자(운영/정산 담당 화면), 공통(화면 구분이 없거나 양쪽).
- 검증 방법: 브라우저(화면에서 직접 확인), 자동(단위)(`npm test`), 자동(DB)(`npm run test:db`, 로컬 Supabase 필요), 브라우저+자동(화면 확인과 자동 테스트 병행), 점검 스크립트(`npm run check:secrets`, `npm run check:trace`), 문서 확인.
- 근거 테스트: 파일 경로와 `it()` 이름(일부는 `it.each` 표시 형식)을 적었고, 자동 근거가 없으면 `-` 입니다. 표 안의 절차는 `<br>`로 구분한 번호 목록입니다.
- 성능 요구사항 PER-001~003은 프로토타입에서 측정하지 않는 목표치라, 케이스는 참고 기록과 문서 확인으로 처리합니다.
