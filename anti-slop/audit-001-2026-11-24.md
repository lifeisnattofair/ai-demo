### 방법

1. 화면마다 1440, 768, 390에서 열고 전체 화면을 캡처했습니다.
2. 자동 측정(화면마다): 콘솔 오류, 가로 넘침(`scrollWidth`와 뷰포트 밖 요소), 44px 미만 누름 요소, 글자 스타일별 대비(글자색과 실제 배경을 조상까지 합성해 계산, 39종 이하 스타일 전수), `h1` 개수와 제목 순서, 랜드마크, `lang`, `title`, 라벨 없는 입력, 이름 없는 컨트롤, `cursor`, 이미지 `alt`/크기/`loading`, 금지 문자(긴 줄표, 가운뎃점, 화살표), 일반 CTA, 과장어, 장식(그림자, 대문자, 넓은 자간, 그라데이션, 블러, 좌측 강조 막대, 반복 애니메이션).
3. Tab 순서: 1440과 390에서 Tab을 30회(390은 15회) 눌러 초점 위치, 초점 표시 여부를 기록했습니다.
4. 클릭 검사(R-26, R-35): 화면별로 보이는 모든 `a`, `button`, `select`, `summary`, 체크/라디오를 하나씩 눌러(매번 화면을 다시 열고) 주소 변화, 펼침 상태, 선택 상태, 대화상자, 경고 문구, 스크롤, DOM 변화를 기록했습니다. 사용자 177개, 회원 화면 64개, 관리자 운영/정산 각각 별도 기록. 되돌릴 수 없는 동작(로그아웃, 탈퇴, 저장, 등록, 승인, 반려, 초기화, 회차 취소)은 누르지 않고 따로 확인했습니다(로그아웃은 별도 세션에서 확인).
5. 예약 흐름: 공연 상세 → 좌석 2석 선택 → 할인 → 결제(카드 선택, 카드사 비움, 약관 전체 동의) → 결제하기 → 결과. 체험, 강좌 선택 화면도 열었습니다.
6. 상태(R-27): Supabase 요청을 2.5초 늦추거나(로딩) 끊어서(오류) 홈, 상세, 내 예약, 알림, 관리자 대시보드, 예약 내역, 결제 내역, 정산을 확인했습니다. 빈 상태는 실제 데이터가 없는 화면에서 확인했습니다.
7. 키보드: GNB(Enter, 아래 화살표, Esc, 마우스 올림), 모바일 전체 메뉴(열기, 아코디언, Esc), 좌석 배치도(화살표, Enter, Space), 관리자 390 메뉴(열기, Esc).
8. 포스터 사진 위 글자는 글자를 숨긴 화면을 캡처해 글자 상자 안 픽셀 밝기의 하위/상위 5%로 최악 대비를 계산했습니다.

### 확인하지 못한 것

- **결제 완료 화면, 예약 상세, 취소/환불, 대기 신청 목록, 알림 목록(데이터 있는 상태), 관리자 표의 데이터 행**: 로컬 Edge Function(`payments-confirm`)이 `worker boot error: failed to determine entrypoint`(503)로 실행되지 않아 결제 승인이 끝나지 않았습니다. DB에 예약이 0건이라 위 화면은 빈 상태와 오류 상태만 확인했습니다. 원인은 Supabase를 다른 경로에서 시작한 실행 환경 문제로 보이며, 스택을 재시작하면 다른 작업에 영향이 있어 손대지 않았습니다.
- 관리자 표 안 행 버튼(상세, 증빙 확인, 환불 등)과 페이지 이동: 데이터 행이 없어 누르지 못했습니다.
- 실제 터치 기기, 화면 낭독기(NVDA, VoiceOver) 낭독 순서, 확대 200% 재배치: 측정하지 않았습니다.
- 성능 수치(LCP, INP, CLS): 측정하지 않았습니다(not measured).
- 다크 모드: 테마 전환이 없어 해당 없음.
- 포스터 사진 위 대비는 근사값입니다(글자 불투명도 0.88, 0.92를 합성하지 않은 값이라 실제는 더 낮습니다).

## 4. Design Read 제안 (승인 후 DESIGN.md에 쓸 초안)

> Reading this as: 공공 문화기관의 예매/수강 신청 서비스(사용자)와 업무용 관리 도구(관리자), 대상은 지역 시민과 가족(사용자), 기관 운영/정산 담당(관리자), 시각 언어는 「포스터가 색을 맡고 UI는 물러나는」 KRDS 기반 편집형(사용자)과 공공 관리자 표준 틀(관리자).

| 다이얼 | 사용자 화면 | 관리자 화면 | 이유 |
|---|---|---|---|
| ENERGY | 2 | 1 | 사용자 화면은 포스터 사진과 큰 타이포그래피가 인사를 맡고 UI는 무채색으로 물러납니다. 관리자는 업무 편의가 1순위라 조용해야 합니다. |
| RHYTHM | 2 | 1 | 홈은 히어로, 포스터 격자, 공지 띠로 몇 군데만 리듬을 바꾸고, 예약 단계는 「한 화면 한 결정」의 같은 틀을 반복합니다. 관리자는 조회 → 목록 → 상세 틀을 모든 화면에서 같게 유지합니다(의도한 균일). |
| MOTION | 1 | 1 | 마우스 올림, 누름(세로 1~2px 이동), 120~200ms 색 전환만 씁니다. 스크롤 등장 효과는 쓰지 않고, 움직임 줄이기 설정이면 모두 끕니다(motion.css 그대로). |

주요 결정과 한 줄 이유(DESIGN.md 초안 항목)

- 색: UI 무채색 + 행동 색 KRDS primary `#256ef4` 하나. 「누를 수 있는 것은 이 색」으로 알아보게 하려고.
- 상품 유형 색 라벨 3종(공연, 체험, 정규 강좌): 목록에서 유형을 글자와 함께 빠르게 구분하려고(색만으로 전달하지 않음).
- 글꼴: Pretendard GOV. KRDS 공공 서비스 표준 글꼴이고 한글 본문 가독성이 검증되어서.
- 정체성 모티프: 사진 위에 얹는 프로그램별 2줄 굵은 제목 포스터. 목록, 상세, 예약 머리에서 반복해 이 기관의 얼굴이 되게.
- 초점: 화면마다 하나. 홈은 추천 공연 포스터와 「예매하기」, 상세는 포스터와 회차 선택, 예약 단계는 오른쪽 요약의 다음 단계 버튼.
- 카드: 목록만 포스터 비율(3:4) 카드 격자. 포스터를 비교해 고르는 화면이라서. 나머지 화면은 표와 목록을 씁니다.
- 그림자: 떠 있는 층(열린 GNB, 대화상자, 모바일 메뉴)에만.
- 테마: 밝은 화면 고정. KRDS 공공 서비스 기준과 포스터 사진의 색 재현을 위해.
- 관리자 아이콘: 좌측 메뉴 묶음 5개에만, 묶음을 빠르게 찾는 표식으로.
- 예외 기록 후보(사용자 결정 필요): 좌석 배치도 좌석 크기(#4), 날짜 입력의 브라우저 기본 표기(#25), 출연자 표기 방식(#14), 가입 3단계 이름(#16).
